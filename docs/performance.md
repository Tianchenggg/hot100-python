# 判题性能

提交时使用最多 2 个全新的 Python Worker 并行评测。每个 Worker 只执行一个用例，结束后销毁；不会通过反复清空全局变量来复用已执行过代码的 Python 环境。

一次运行或提交结束后，会准备 1 个尚未执行用户代码的 Worker，供下次点击使用。准备完成后闲置 60 秒即释放；停止运行或离开页面时也会释放。网页初次打开和编辑代码时不会启动判题。

## 实测结果

2026-10-04，在同一台 Apple M4、macOS arm64、Node.js v26.8.1 上测试。使用 Node `worker_threads` 适配浏览器 Worker 接口，加载本地已缓存的 Pyodide 0.27.7；没有 CDN 下载耗时。

测试代码读取两个整数并输出和，依次运行 8 个不同输入。每轮分别执行串行和并行配置，共 3 轮；每次验证全部输出正确。计时覆盖整个 `runCases` 调用，包括新 Worker 的启动、Python 初始化、通信和代码执行。

| 调度配置 | 第 1 轮 | 第 2 轮 | 第 3 轮 | 中位数 |
| --- | ---: | ---: | ---: | ---: |
| 每例全新 Worker，串行 | 5490 ms | 5521 ms | 5818 ms | 5521 ms |
| 每例全新 Worker，最多 2 个并行 | 2982 ms | 3110 ms | 3179 ms | 3110 ms |

这组测试的总耗时中位数减少 **44%**。两组均关闭运行后的预热，以单独比较提交调度的变化。

串行基线使用当前运行器的 `maxConcurrency: 1, warmWorkers: 0`，还原旧版逐例创建、初始化、执行、销毁 Worker 的顺序；它是相同执行内核下的配置对比，并非重新打包运行整个旧版网站。

另测一次已完成预热后的单次运行，耗时 **13 ms**。这个数字不包含此前准备 Worker 的时间，也不是多轮中位数；只有干净 Worker 已准备好且尚未过期时，才有这种收益。

## 复现

在仓库根目录运行：

```sh
npm ci
node scripts/runner-benchmark.mjs
```

已有独立 Pyodide 安装时，可指定目录：

```sh
PYODIDE_PACKAGE_PATH=/path/to/node_modules/pyodide node scripts/runner-benchmark.mjs
```

基准输出每轮数据、中位数、耗时下降比例和预热后单次耗时。它是手动运行的性能观察工具，不属于 `npm test`，CI 不要求机器达到某个耗时阈值。

## 隔离与资源边界

- 最多同时调度 2 个 Worker。运行结束后只保留 1 个未使用的 Worker；不是在 2 个正在执行的 Worker 之外再保留额外预热池。
- 每个用例独立加载 Python。已执行代码修改的 `builtins`、模块属性、标准输入、工作目录和虚拟文件不会传给下一例。
- 每例执行限时 5 秒，标准输出、标准错误和返回值合计上限 64 KiB。停止或超时会销毁对应 Worker。
- 限制 Worker 数量可以避免无界并发，但不是 Python 内存配额。单个程序分配的内存仍受浏览器和设备条件影响。

隔离、并发上限、按序回报、超时、取消、输出限制、预热不执行用户代码及闲置释放由 `scripts/runner-test.mjs` 验证。

首次运行仍需下载并初始化 Pyodide。这里的本地缓存测试不能代表首次访问、移动设备或所有浏览器，也不保证每次运行都快 44%。代码本身的耗时、设备负载和网络状态都会影响实际等待时间。页面结果展示包含环境准备和判题的总耗时；悬停可查看 Python 执行时间合计。

运行环境依据 [Pyodide 0.27.7 Worker 文档](https://pyodide.org/en/0.27.7/usage/webworker.html) 和 [JavaScript API](https://pyodide.org/en/0.27.7/usage/api/js-api.html)；未使用隐藏的内存快照恢复接口。
